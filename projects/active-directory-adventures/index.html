Active Directory Adventures

In my Portable Homelab project I talked about setting up the hardware side of things. I decided that it was too much to talk about in one project, so I split it up. If you want to know about the hardware, go to this page.
So what is my goal for this project? I want to learn Active Directory. I asked my teachers and got some guidance, along with information from my book, which has VM guidelines for the labs. With that, I started the first version of my ADLab.

The initial setup

I created 3 VMs:

Name OS IP Purpose
pfSense pfSense 10.0.0.1 This is just to route traffic between networks.
DC01 Windows Server 2025 10.0.0.10 This is the main PC that I will probably use. It's the root domain controller.
CLIENT01 Windows 11 Pro 10.0.0.11 This will be the first client on the network.

The first thing I configured was the pfSense firewall. I set it up so that it would take the Wi-Fi and translate it to a private Hyper-V switch. I created the internal network with the IP range 10.0.0.0/24 and connected the v-switches. I acquired a Windows Server eval and a Windows 11 ISO and created the other two VMs. As stated in the table, each device was named and given an IP. Since pfSense was used, the DNS requests were handled by it, but I decided I'd figure that out when I got AD DS installed.
Now it was time for Active Directory. I loaded up DC01, installed AD DS, and promoted it to domain controller. I set up the domain adlab.test and enabled DNS. With that done, I set up CLIENT01 and connected it to the domain. I was able to ping DC01 from CLIENT01 at this point, but that's mostly because of pfSense. pfSense was still handling most of the networking. To fix this, I installed the DHCP service on DC01, set the scope under adlab.test, and configured pfSense to redirect DHCP and DNS requests to DC01. I was now able to connect CLIENT01 with DHCP without assigning the IP manually.
With the devices up, I was able to get started with users and permissions.

I created these users in ADUC and sorted them into organizational units. I turned on CLIENT01 and was able to log in to each user account. Now I needed permissions. I learned about Microsoft AGDLP, which is the best practice Microsoft recommends for setting up permissions. So I created Accounting, IT, Management, and Sales global groups and assigned the respective users to each GG. I then created Domain Local Groups to assign to the Global Groups to give permissions. I didn't have much to grant permission to, so I just created some that would allow modification of folders. I didn't have any folders to share, however, so I needed to get that working. To do that, I needed more power, which is why I decided to go on a side quest to build the portable homelab.

Internetworked Design: Split setup

I have a second computer connected to my school laptop at this point. If you want details, go here and see section 2. Now that I had a second computer, I needed to network the devices so they could talk to each other. I already had the 10.0.1.0/31 network connecting the two computers, so I decided to just use that network. I set up the external virtual switch in Hyper-V and linked them to the Ethernet port. I configured pfSense to use the Ethernet port as LAN2 and then set up a firewall rule to allow traffic between the two networks.
Because DHCP and DNS forwarding were set up on the pfSense network, I was able to just add the new network scope to DC01 and connect devices to the new external network.

With the users and computers sorted, it was time for file sharing. I created Accounting, IT, and Sales folders at D:\Company\ on the FS01 server. I shared the folders and allowed only the domain local groups to access their specific folders. To test if it worked, I logged in as ajohnson and attempted to access \\FS01\Accounting. It resolved, and I was able to create and modify files. I then logged in as edavis, tried to access the same folder, and was denied permission.

This is pretty much as far as I've gotten. The next goal is to move everything to the server laptop. I bought more RAM and should be able to run the full network off of the one workstation. I just have to get it installed and the files moved over. For now I will leave this here as it is, and update it when I get it up and working.
